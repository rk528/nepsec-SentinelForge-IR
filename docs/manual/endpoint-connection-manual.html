1. How endpoint collection works

A small shipper runs on each machine every five minutes. It reads the machine's own security logs since its last run and posts them over HTTPS to SentinelForge with that machine's ingest key. Nothing listens on the machine and no inbound port is opened.

Ubuntu Desktop / Serversystemd journal: SSH, sign-ins, sudo, user and group changes, services stopping
WindowsSecurity, System and Sysmon event logs
→
Shipper (every 5 min)Linux: systemd timer running a Python script as a locked account.
Windows: scheduled task running a PowerShell script as SYSTEM.
→
SentinelForge IRHTTPS 443 to sentinelforge-api.kuinkel.com. Events are normalised and the detection rules run immediately.

What each machine contributes

MachineCollectedDetections that use it
Ubuntu DesktopGreeter (GDM/LightDM) and console sign-ins and failures, sudo commands and failed sudo/su passwords, account and group changesSF-IAM-001 new privileged account; investigations
Ubuntu ServerSSH logins and failures with source IP, sudo commands, useradd/usermod/gpasswd, auditd/rsyslog/journald stoppingSF-AUTH-001 password guessing, SF-IAM-001, SF-DEF-001 logging stopped
WindowsLogons (with logon type), process creation, scheduled task creation, account and group changes, log clearing, services stopping; with Sysmon also LSASS access, Run-key writes, network and DNSSF-AUTH-001, SF-PROC-001, SF-IAM-001, SF-DEF-001, SF-CRED-001, SF-PERS-001/002, SF-LAT-001

Before you start

  • A SentinelForge admin account (demo accounts cannot create data sources).
  • Administrator rights on each machine: sudo on Ubuntu, a local Administrator on Windows.
  • Outbound HTTPS (TCP 443) from each machine to sentinelforge-api.kuinkel.com. Check with curl -sI https://sentinelforge-api.kuinkel.com/api/v1/health (Ubuntu) or Invoke-RestMethod https://sentinelforge-api.kuinkel.com/api/v1/health (Windows).
  • The connector files from the repository: connectors/linux/ (two files) and connectors/windows/Send-WindowsEvents.ps1.
Treat ingest keys like passwordsAnyone with a key can send events as that machine. Paste it only into the installer prompt or the machine-level setting described below, never into scripts, tickets or chat. If a key leaks, rotate it (chapter 7).

2. Create a data source and ingest key

Create one data source per machine. Each gets its own key, and Settings shows each machine's health separately.

1

Sign in at https://sentinelforge.kuinkel.com as an admin and open Settings (bottom of the left menu). Scroll to Data sources and click Add source.

2

Name it after the machine's host name and choose the type:

MachineType
Ubuntu Desktop or Serverlinux
Windows (with or without Sysmon)windows_security
3

Click Create and show key. Copy the key that starts with sfk_ with the Copy button. It is shown once; only a hash is stored. Click I have stored it.

3. Ubuntu Desktop

Works on Ubuntu Desktop 20.04, 22.04, 24.04 and later (GNOME, and other desktops that use LightDM or SDDM). The installer sets everything up; you need the two files from connectors/linux/ and the ingest key from chapter 2.

3.1 Get the files onto the desktop

Use whichever is easiest:

  • USB stick: copy the connectors\linux folder from the repository to the stick, plug it into the Ubuntu desktop, and copy the folder to your home folder as sentinelforge using the Files app.
  • From a Windows PC over the network: on the Ubuntu desktop install the SSH server once (sudo apt install -y openssh-server) and find its address with hostname -I. Then in PowerShell on the Windows PC:
scp -r C:\path\to\sentinal-IR\connectors\linux  maya@192.168.1.50:~/sentinelforge

3.2 Install

1

Open Terminal: press Ctrl + Alt + T, or open Show Apps and search for “Terminal”.

2

Run the installer and paste the ingest key when asked. Nothing appears while you paste; that is normal for secret input. Press Enter.

maya@ubuntu-desk-07: ~/sentinelforge
maya@ubuntu-desk-07:~$ cd ~/sentinelforge
maya@ubuntu-desk-07:~/sentinelforge$ sudo bash install.sh --api-url https://sentinelforge-api.kuinkel.com
[sudo] password for maya:

4. Ubuntu Server

Works on Ubuntu Server 20.04 and later, including cloud images. The steps are the same as for the desktop, done over SSH.

4.1 Copy the files and connect

From the Windows PC that has the repository (PowerShell), copy the folder, then sign in to the server:

scp -r C:\path\to\sentinal-IR\connectors\linux  deploy@203.0.113.10:~/sentinelforge
ssh deploy@203.0.113.10

Using PuTTY or WinSCP instead works the same way: copy the two files into ~/sentinelforge and open a session.

4.2 Make sure the journal is kept on disk

Standard installs keep it in /var/log/journal. Minimal and some cloud images keep it only in memory, so events from before a reboot would be lost:

ls -d /var/log/journal || { sudo mkdir -p /var/log/journal && sudo systemctl restart systemd-journald; }

4.3 Install

deploy@ubuntu-srv-01: ~/sentinelforge
deploy@ubuntu-srv-01:~$ cd ~/sentinelforge && ls

deploy@ubuntu-srv-01:~/sentinelforge$ sudo bash install.sh --api-url https://sentinelforge-api.kuinkel.com

4.4 Safe test: SSH password guessing

From another computer, try a wrong password 6 times for a real account, then sign in correctly from the same computer:

ssh deploy@203.0.113.10      # enter a wrong password 6 times, then the right one

Within 5 minutes an SF-AUTH-001 alert appears. It shows the failures, the successful login and the source address:

Password logins onlyIf the server allows only SSH keys (PasswordAuthentication no, recommended), failed attempts are still recorded but this rule cannot fire because nobody can log in with a guessed password.

5. Windows workstations and servers

Works on Windows 10, Windows 11 and Windows Server 2016 or later. A PowerShell script runs every 5 minutes as a scheduled task. Do these steps in PowerShell as Administrator: open Start, type “PowerShell”, right-click Windows PowerShell → Run as administrator.

5.1 Turn on the auditing the detections need

On a domain, set these in a Group Policy for the machines (Computer Configuration → Policies → Windows Settings → Security Settings → Advanced Audit Policy Configuration). On a single machine:

auditpol /set /subcategory:"Logon" /success:enable /failure:enable
auditpol /set /subcategory:"Process Creation" /success:enable
auditpol /set /subcategory:"User Account Management" /success:enable /failure:enable
auditpol /set /subcategory:"Security Group Management" /success:enable
auditpol /set /subcategory:"Other Object Access Events" /success:enable
reg add "HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System\Audit" /v ProcessCreationIncludeCmdLine_Enabled /t REG_DWORD /d 1 /f

“Other Object Access Events” records scheduled tasks being created (event 4698). The last line adds command lines to process events.

Optional but recommended: SysmonInstall Sysmon with a community configuration (for example SwiftOnSecurity's or Olaf Hartong's). It adds LSASS access (credential dumping), Run-key writes (persistence), network connections and DNS queries. The shipper picks it up automatically and sends only LSASS access and Run-key events from those two high-volume types.

5.2 Install the shipper

1

Copy connectors\windows\Send-WindowsEvents.ps1 to C:\SentinelForge\ on the machine.

2

Store the ingest key (type windows_security, chapter 2) at machine level, so it never appears in the task's command line:

[Environment]::SetEnvironmentVariable("SENTINELFORGE_INGEST_KEY", "sfk_paste_your_key_here", "Machine")
3

Open a new Administrator PowerShell window (so it sees the key) and run the shipper once:

Administrator: Windows PowerShell
PS C:\WINDOWS\system32> powershell -NoProfile -ExecutionPolicy Bypass -File C:\SentinelForge\Send-WindowsEvents.ps1 -ApiUrl https://sentinelforge-api.kuinkel.com
2026-10-28 13:42:15Z sent 214 events, 214 new, 2 alerts raised

Illustration of the expected output. The first run reads the last 60 minutes.

4

Schedule it every 5 minutes as SYSTEM:

$action  = New-ScheduledTaskAction -Execute "powershell.exe" -Argument '-NoProfile -ExecutionPolicy Bypass -File "C:\SentinelForge\Send-WindowsEvents.ps1" -ApiUrl https://sentinelforge-api.kuinkel.com'
$trigger = New-ScheduledTaskTrigger -Once -At (Get-Date) -RepetitionInterval (New-TimeSpan -Minutes 5)
Register-ScheduledTask -TaskName "SentinelForge event shipper" -Action $action -Trigger $trigger -User "SYSTEM" -RunLevel Highest

Check it in Task Scheduler → Task Scheduler Library → SentinelForge event shipper: “Last Run Result” should be The operation completed successfully (0x0).

Expected one-time alertBecause this task runs PowerShell, registering it raises one SF-PERS-001 Suspicious scheduled task alert for the machine. Close it as benign positive; it is SentinelForge noticing its own installation.

6. Verify: events and alerts

After a machine's first run, check three places in SentinelForge.

  1. Settings → Data sources: the machine shows Reporting, an event count and “last … ago” (Figure 3). A source that stays Stale has not delivered anything; see chapter 7.
  2. Events: type the host name in the host box and click Apply (Figures 4, 6, 7). Click any timestamp to see the full record, including the original log fields.
  3. Alerts: detections raised from the machines' events, newest first:

Open an alert to see why it fired, the matching events and the rule's known false positives, then acknowledge, close with a decision, or escalate it to an incident.

Everyday tasks

TaskUbuntuWindows
Run nowsudo systemctl start sentinelforge-shipper.serviceTask Scheduler → right-click the task → Run

Re-send recent historysudo rm /var/lib/sentinelforge/journal.cursorDelete C:\ProgramData\SentinelForge\windows-events.state
Uninstallsudo bash install.sh --uninstallUnregister-ScheduledTask "SentinelForge event shipper", delete C:\SentinelForge, and clear the key: [Environment]::SetEnvironmentVariable("SENTINELFORGE_INGEST_KEY", $null, "Machine")

Re-sending is safe: SentinelForge ignores events it already has. If the API cannot be reached, the shippers keep their place and catch up on the next run.

Common problems

SymptomCause and fix
HTTP 401: Missing or invalid ingest keyWrong, rotated or revoked key. Copy a new one (Rotate key) and update the machine.
HTTP 429 / “Too many requests”Rate limit per source (60 requests a minute). The shipper retries; persistent 429s mean several machines share one key: give each its own.
API unreachable / timeoutOutbound HTTPS is blocked. Allow TCP 443 to sentinelforge-api.kuinkel.com; check a proxy.
Ubuntu: journalctl failedThe account cannot read the journal. Re-run the installer, which adds sentinelforge to systemd-journal.
Ubuntu: runs fine but “sent 0”No security events since the last run; normal on a quiet machine. Use --dry-run --lookback-minutes 600 to see recent candidates.
Windows: “Set SENTINELFORGE_INGEST_KEY…”The key was set in a window opened earlier, or for the user instead of the machine. Set it with "Machine" and open a new window.
Windows: no process command linesThe registry setting in 5.1 is missing; apply it and wait for new processes.
Windows: no scheduled-task or LSASS events“Other Object Access Events” auditing is off, or Sysmon is not installed / not configured for events 10 and 13.
Source stays StaleCheck the last run on the machine first; any HTTP error message names the problem.

Security checklist

  • One data source and key per machine.
  • Keys only in the installer prompt (Ubuntu) or the machine environment variable (Windows).
  • Rotate a machine's key when it is rebuilt, sold or given to someone else; revoke it when the machine is retired.
  • Close the shipper's own SF-PERS-001 alert on Windows as benign positive, once per machine.
  • Review new alerts daily; each one links to the events that caused it.
